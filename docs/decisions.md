# Approved Decisions & Architecture Decision Records (ADRs)

## Foundational Decisions (D1 - D9)

- **D1 (Timeline)**: Jan 2025 to Jun 2026 (18 months), prediction cut-off date `2026-01-01`.
- **D2 (Churn Label Horizon)**: 180 days after the prediction date.
- **D3 (Offer Outcome Window)**: 90 days after contact.
- **D4 (Churn Distribution)**: Overall churn about 12% over 18 months (bounded strictly within 5% - 20%).
- **D5 (Experiment Split)**: Treatment/control split 50/50, stratified by risk band.
- **D6 (Anomaly Injection Scale)**: About 40 injected records per anomaly type, parameterized (10 in starter scale).
- **D7 (Ground Truth Isolation)**: Anomaly labels and potential outcomes live only in `ground_truth/`, with no `issue_type` column in main tables.
- **D8 (Offer Catalogue)**: Three offers: 10% discount (6 mo), 20% discount (3 mo), 1 free month, each with cost and margin cap.
- **D9 (Repository Data Footprint)**: Starter dataset (1,000 subscribers) committed in all formats. Full 20k dataset generated via CLI; committed if full CSV is under 50 MB, otherwise committed as starter + SHA-256 manifests.

## Technical Stack & Determinism
- **Stack**: Python 3.11, NumPy/pandas, SQLite 3, scikit-learn, FastAPI + uvicorn, Streamlit, Plotly, pytest.
- **Fixed Seed**: `20261022` via master `SeedSequence`.

## Architecture Decision Records (ADR-001 to ADR-012)

| ADR | Problem | Decision | Trade-off |
| :--- | :--- | :--- | :--- |
| **001** | Architecture style | Modular monolith, single package `churnexp` | Less horizontally scalable across teams; far faster to build, test, and explain. |
| **002** | Where rules live | DB enforces structure (PK, FK, NOT NULL, enums, basic CHECK). Validators enforce business rules (temporal ordering, eligibility, group exclusivity, attribution). | Anomalies must load into SQLite to be detected; business rules cannot be rigid database CHECK constraints. |
| **003** | History tracking | Status is never an in-place mutable column. Plan changes instantiate new `Subscription` rows (`-02`) linked by `previous_subscription_id`. Transitions log to append-only `StateEvent`. | Current status is derived from events and views. |
| **004** | Data leakage | Dual temporal snapshot design: Training $P_0 = \text{2025-07-01}$ (features Jan-Jun 2025, labels 180d), Scoring $P = \text{2026-01-01}$ (features Jul-Dec 2025). Valid rule: $\text{event\_date} < \text{as\_of\_date}$. | Requires dual-pass feature builder and strict temporal filtering logic. |
| **005** | Causal truth | Latent potential outcomes (`persuadable`, `sure-thing`, `lost-cause`) stored in `ground_truth/`. | Generator is more complex; evaluation benchmark is mathematically grounded. |
| **006** | Ground truth separation | Isolated directory; no `issue_type` in main tables. Detectors run blind; audit module scores performance. | Model, feature, and evaluation code cannot import `audit` or read `ground_truth/` (enforced by AST test). |
| **007** | Experiment structure | Planned offer assigned first, then 50/50 stratified arm randomization. Control gets `WITHHELD` status with offer preserved. Primary metric: Intention-To-Treat (ITT) lift. | Requires larger eligible pool; guarantees unbiased program- and offer-level lift. |
| **008** | Determinism | Single master `SeedSequence(20261022)`, spawned into per-entity substreams keyed by customer index. Sorted output; no wall-clock timestamps. | Requires discipline in RNG handling and array sorting. |
| **009** | Data in Git | Starter dataset (1,000 subscribers) committed. Full 20k generated by CLI; committed only if CSV total is comfortably under 50 MB, else starter + checksums. | Reviewer inspects starter immediately; full data reproduces deterministically. |
| **010** | Predictive model | Explainable Logistic Regression with standardized features as primary; Gradient Boosting as optional secondary benchmark. | Marginally lower raw AUC; delivers transparent coefficient interpretations. |
| **011** | Serving architecture | FastAPI service is read-only. Streamlit calls shared domain services directly. | Eliminates unnecessary inter-process network hops in demo mode while preserving REST contracts. |
| **012** | Model evaluation purity | Model evaluation uses untreated cohorts only (control, untargeted, ineligible). | Reduces sample size for model evaluation; guarantees uncorrupted baseline metrics. |
| **013** | Anomaly injection | Deterministic injection of four operational anomaly types (A-D) at pipeline tail. | Requires isolated ground-truth references for downstream verification. |
| **014** | Blind detectors | Detectors evaluate business rules blind to ground truth and latent parameters. | Operates without ground truth; audited independently against latent truth. |
| **015** | Ground truth audit | Compare blind detector findings and ITT lift against hidden ground truth. | Audit code strictly isolated from runtime and evaluation pipelines. |
| **016** | Experiment evaluation | Filter detector-flagged records; ITT lift with analytical 95% CIs; integer-cent financial metrics. | Excludes corrupt contacts; preserves causal inference. |
